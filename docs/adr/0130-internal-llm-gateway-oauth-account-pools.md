# ADR 0130 — Internal LLM Gateway with OAuth Account Pools and Out-of-Band Snapshot Renewal

Status: Accepted, 2026-10-28.
Extends: [ADR 0003](0003-provider-boundaries.md), [ADR 0023](0023-zero-provider-retries.md), [ADR 0062](0062-credential-free-provider-config.md), [ADR 0083](0083-admin-managed-resource-credentials.md), [ADR 0099](0099-agent-job-responses-provider-routing.md).

`voice-agent-server` introduces an internal LLM Gateway (`services::llm_gateway` and `providers::llm::gateway`, adapter `"llm_gateway"`) supporting five upstream vendors (`anthropic`, `openai_codex`, `gemini`, `github_copilot`, and `muse`) without exposing an unauthenticated external `/v1` proxy endpoint. OAuth and session token bundles (`access_token`, `refresh_token`, `upstream_oauth_token`, `account_context_id`) are persisted in a dedicated `llm_gateway_accounts` table where each record's `credential_json` is sealed with AES-256-GCM via `SecretResolver::seal` (`scope = "gateway_account:<account_key>"`) using URL-safe unpadded Base64 encoding to satisfy `credentials::valid_input`. Provider configurations (`config_json`) remain credential-free under ADR 0062 by storing only a strongly-typed `gateway_binding` (`"account:<account_key>"` or `"pool:<vendor>"`). `LlmGatewayHub` pre-decrypts enabled accounts into an in-RAM `GatewayRuntimeSnapshot` and refreshes expiring tokens out-of-band via a single-flight background renewal loop (`proactive_refresh_expiring`, using a 30-minute renewal margin for `muse` and self-healing cookie-backed `muse` accounts out of transient `reauth_required` states while placing transient renewal errors into a 60-second cooldown). At runtime, `LlmGatewayProvider` selects a healthy account in `0ms` from the in-RAM snapshot; if an upstream call fails before emitting any token delta with `401 Unauthorized` (`AuthInvalid`), it performs at most one single-flight `try_refresh_on_unauthorized` renewal and retry on that account, and for `pool:<vendor>` bindings rotates across up to `MAX_POOL_FAILOVER_ATTEMPTS` healthy accounts on pre-emission retryable upstream errors (`401`, `429`, or transient transport errors). For `muse`, session and Hatch VM WebSocket renewal uses a 3-tier fallback (`GET /api/session` + `POST /api/hatch/token` with 2-attempt retry -> `GET /` SSR/RSC stream extraction -> headless Chromium CDP fallback), and runtime-bootstrapped `wss_url` / rotated cookies from `SharedMusePool` are persisted asynchronously in the background to `LlmGatewayHub`. Muse accounts are connected only by pasting session cookies (`login_mode = cookie_paste`, `POST /api/admin/llm-gateway/accounts/cookie-import`): there is no interactive browser login or OAuth session for this vendor, cookies upstream reports as unauthorized are rejected at import, and an unreachable upstream does not block the import because renewal retries later.

## Considered Options

- **Storing OAuth tokens inside `providers.credential_json` vs. dedicated `llm_gateway_accounts` table with `GatewayBinding`**: Binding OAuth tokens directly to a Provider instance prevents sharing an account pool across multiple providers and forces every background token refresh (every 30–60 minutes) to mutate the `providers` table and bump `revision`; decoupling `GatewayAccount` rows from `providers` lets multiple providers bind to `"account:<key>"` or `"pool:<vendor>"` while token refreshes happen transparently inside `LlmGatewayHub`.
- **Unbounded in-call retries vs. bounded pre-emission `401` single-flight refresh and pool failover with stateful RAM cooldowns**: Retrying after tokens have already been emitted violates stream determinism under ADR 0023; restricting recovery to a single pre-emission `try_refresh_on_unauthorized` attempt per account and bounded pre-emission `pool:<vendor>` failover (`MAX_POOL_FAILOVER_ATTEMPTS`) while marking rate-limited/unauthorized accounts in RAM preserves deterministic streaming semantics and self-heals expired OAuth/Hatch VM sessions automatically.
- **Routing OAuth vendors through `llm::builder::LLMBuilder` (`ConfiguredOpenAiLlm`) vs. dedicated `LlmGatewayProvider` (`reqwest` SSE)**: `LLMBuilder` cannot attach vendor-mandatory OAuth headers (`anthropic-beta: oauth-2025-04-20`, `Editor-Version`, `Copilot-Integration-Id`, `ChatGPT-Account-Id`); a dedicated `LlmGatewayProvider` implementing both OpenAI-compatible SSE (`wire_openai`) and Anthropic Messages SSE (`wire_anthropic`) over `reqwest` encapsulates all vendor wire differences behind the `LlmProvider` seam and delegates `OpenAiConfig` instances that specify `gateway_binding` to the same implementation.
