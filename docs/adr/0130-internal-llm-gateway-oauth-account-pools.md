# ADR 0130 — Internal LLM Gateway with OAuth Account Pools and Out-of-Band Snapshot Renewal

Status: Accepted, 2026-10-28.
Extends: [ADR 0003](0003-provider-boundaries.md), [ADR 0023](0023-zero-provider-retries.md), [ADR 0062](0062-credential-free-provider-config.md), [ADR 0083](0083-admin-managed-resource-credentials.md), [ADR 0099](0099-agent-job-responses-provider-routing.md).

`voice-agent-server` introduces an internal LLM Gateway (`services::llm_gateway` and `providers::llm::gateway`, adapter `"llm_gateway"`) supporting five upstream vendors (`anthropic`, `openai_codex`, `gemini`, `github_copilot`, and `muse`) without exposing an unauthenticated external `/v1` proxy endpoint. OAuth and session token bundles (`access_token`, `refresh_token`, `upstream_oauth_token`, `account_context_id`) are persisted in a dedicated `llm_gateway_accounts` table where each record's `credential_json` is sealed with AES-256-GCM via `SecretResolver::seal` (`scope = "gateway_account:<account_key>"`) using URL-safe unpadded Base64 encoding to satisfy `credentials::valid_input`. Provider configurations (`config_json`) remain credential-free under ADR 0062 by storing only a strongly-typed `gateway_binding` (`"account:<account_key>"` or `"pool:<vendor>"`). To honor ADR 0083's prohibition on runtime SQL queries and per-request secret decryption while supporting short-lived OAuth or Hatch VM tokens, `LlmGatewayHub` pre-decrypts enabled accounts into an in-RAM `GatewayRuntimeSnapshot` and refreshes expiring tokens out-of-band via a single-flight background renewal loop. To honor ADR 0023's zero-retry rule, `LlmGatewayProvider` performs exactly one upstream attempt per call using a healthy account selected in `0ms` from the in-RAM snapshot; if an account returns HTTP `429` or `401`, `report_outcome` marks that account's cooldown or re-authentication state in RAM so subsequent calls to `pool:<vendor>` route to the next available account.

## Considered Options

- **Storing OAuth tokens inside `providers.credential_json` vs. dedicated `llm_gateway_accounts` table with `GatewayBinding`**: Binding OAuth tokens directly to a Provider instance prevents sharing an account pool across multiple providers and forces every background token refresh (every 30–60 minutes) to mutate the `providers` table and bump `revision`; decoupling `GatewayAccount` rows from `providers` lets multiple providers bind to `"account:<key>"` or `"pool:<vendor>"` while token refreshes happen transparently inside `LlmGatewayHub`.
- **In-call retry loop on `429` vs. single-attempt selection with stateful RAM cooldown eviction**: Retrying across multiple accounts inside `LlmProvider::stream` violates ADR 0023 (Zero Provider Retries) and adds unpredictable tail latency to real-time voice turns; selecting a non-cooled-down account from RAM before the single upstream attempt (`0ms`) and evicting rate-limited accounts into a timed RAM cooldown on `429` preserves deterministic single-attempt execution while rotating subsequent turns across the pool.
- **Routing OAuth vendors through `llm::builder::LLMBuilder` (`ConfiguredOpenAiLlm`) vs. dedicated `LlmGatewayProvider` (`reqwest` SSE)**: `LLMBuilder` cannot attach vendor-mandatory OAuth headers (`anthropic-beta: oauth-2025-04-20`, `Editor-Version`, `Copilot-Integration-Id`, `ChatGPT-Account-Id`); a dedicated `LlmGatewayProvider` implementing both OpenAI-compatible SSE (`wire_openai`) and Anthropic Messages SSE (`wire_anthropic`) over `reqwest` encapsulates all vendor wire differences behind the `LlmProvider` seam and delegates `OpenAiConfig` instances that specify `gateway_binding` to the same implementation.
