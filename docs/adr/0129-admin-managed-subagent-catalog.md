# ADR 0129 — Admin-Managed Sub-Agent Catalog with Built-in Specs and Custom Sub-Agents per Flow

Status: Accepted, 2026-10-28.
Extends: [ADR 0127](0127-orchestrator-flow-task-and-wiki-runtime.md), [ADR 0128](0128-admin-managed-job-skill-catalog.md).

`voice-agent-server` unifies the 2 Root Orchestrators (`daily_root`, `wiki_root`), 7 Built-in Sub-Agents (`is_builtin = true`), and Admin-created Custom Sub-Agents (`is_builtin = false`) under `PersistedBackgroundSettings` (`agent_settings.json`) and exposes `POST /api/admin/background/agents` and `DELETE /api/admin/background/agents/{id}` guarded by `If-Match: "<revision>"`. Built-in Sub-Agents retain embedded defaults (`AGENT_SPECS`) for one-click restoration and reject deletion (`builtin_subagent_cannot_be_deleted`), whereas Custom Sub-Agents are bound to an explicit Flow (`flow_id` in `{"daily", "wiki"}`), restricted to that Flow's tool pool (`CUSTOM_DAILY_SUBAGENT_TOOLS` vs. collector-free `CUSTOM_WIKI_SUBAGENT_TOOLS`), materialized to `<prompts_dir>/<id>.md` alongside an auto-generated `<active_subagents>` block in the parent Root Orchestrator's prompt file on disk, and hot-applied via `Orchestrator::reconfigure` without restarting the server or interrupting in-flight `AgentRun`s.

## Considered Options

- **Separate `custom_subagents.json` / SQLite table vs. single `PersistedBackgroundSettings` (`agent_settings.json`) owner**: Introducing a second store for Custom Sub-Agents splits concurrency tokens and causes dual-source race conditions with `PUT /api/admin/background/settings`; storing Custom Sub-Agent definitions inside `PersistedBackgroundSettings.agents` (distinguished by `!find_agent_spec(id)` + `flow_id`) keeps a single `background_revision` (`If-Match`) and makes `write_agent_prompts` a pure projection from `PersistedBackgroundSettings`.
- **Unrestricted tool selection vs. per-Flow tool pools**: Allowing Flow 2 (`wiki_root`) Custom Sub-Agents to select external collector tools (`yt_fetch_transcript`, `fetch_html`, `anydoc_inspect_pdf`) violates the Karpathy LLM Wiki invariant that Flow 2 only compiles and curates local `sources/` into `wiki/`; enforcing `custom_subagent_flow_policy(flow_id)` at both validation and resolution time preserves Flow 1 / Flow 2 isolation.
- **Requiring manual Root Orchestrator prompt edits vs. dynamic `<active_subagents>` disk injection**: Expecting Admins to manually edit `daily_root` or `wiki_root` Markdown prompts whenever a Sub-Agent is added, disabled, or deleted is error-prone and pollutes the Root prompt's customization state; appending `<active_subagents>` (listing currently enabled Built-in and Custom Sub-Agents and their descriptions) to `<prompts_dir>/daily_root.md` and `wiki_root.md` during `write_agent_prompts` lets Root Orchestrators immediately discover and delegate to newly enabled Custom Sub-Agents while keeping the Admin-visible `system_prompt` clean.
