# ADR 0131 — Online Database Backup Export and Key-Mapped Transactional Import

Status: Accepted, 2026-10-30.
Supersedes (backup/restore scope): [ADR 0057](0057-database-enabled-startup-dependency.md), [ADR 0063](0063-forward-only-schema-migrations.md).
Extends: [ADR 0058](0058-minimal-admin-mutation-audit.md), [ADR 0071](0071-versioned-provider-runtime-manager.md), [ADR 0083](0083-admin-managed-resource-credentials.md), [ADR 0127](0127-orchestrator-flow-task-and-wiki-runtime.md), [ADR 0130](0130-internal-llm-gateway-oauth-account-pools.md).

`voice-agent-server` provides authenticated Admin backup export, read-only Backup Inspection, and online transactional restore through a single deep module `database::backup` exposed at `/api/admin/system/backup/*`. Exports produce either a portable key-indexed **Database Backup Bundle** (`.json`) or a consistent **Database Snapshot** (`.db` via `VACUUM INTO`), and both formats are imported online by projecting the backup into a business-key bundle and applying it inside one `BEGIN IMMEDIATE` transaction that preserves `ADR 0071`'s monotonic `ProviderVersion` invariant, keeps resource-key-bound sealed credentials encrypted (`ADR 0083`), records an atomic `admin_audit_events` entry (`ADR 0058`), and invalidates/reloads in-RAM caches upon commit.

## Considered Options

- **In-place `.db` file replacement while the server is running vs. read-only `.db` extraction into key-mapped transactional import**: Overwriting `voice-agent.db` while `SqlitePool`, `HistoryWriter`, and `ReminderScheduler` hold open WAL/SHM descriptors corrupts the database and reuses stale `(provider_id, desired_revision)` pairs in `ProviderRuntimeManager` (violating `ADR 0071`); opening uploaded `.db` snapshots read-only in a temporary file (`trusted_schema = OFF`, `cell_size_check = ON`) and applying changes transactionally by business key supports both `.json` and `.db` imports online without process restarts or WAL corruption.
- **Plaintext credential export or hard failure on key mismatch vs. preserving AAD-sealed ciphertext with optional scrub (`clear_unreadable_credentials`)**: Because `CredentialCipher` seals credentials with natural-key AAD (`provider:<key>`, `mcp:<key>`, `gateway_account:<account_key>`, `notification_channel:<kind>`), ciphertext remains valid across row-ID remapping on the same master key; on cross-deployment import with a different master key, `clear_unreadable_credentials` scrubs only unreadable records (`NULL` for nullable columns, or `"{}"` with `status = 'reauth_required'` for `llm_gateway_accounts.credential_json NOT NULL`) so configuration imports succeed safely.
- **Naive table operations vs. singleton `web_assistant` matching and reverse-topological deletion in `ImportMode::Replace`**: Matching the `kind = 'web_assistant'` Virtual Device by `kind` (including its `history_messages` and `device_reminders` foreign keys) avoids `ux_devices_single_web_assistant` collisions, while reverse-topological deletion with explicit `speaker_quick_captures` cleanup, `notifications_inbox.dedup_key` deduplication, and `device_reminder_sync` revision reconciliation prevents `CHECK`, `UNIQUE`, and `ON DELETE RESTRICT` failures.
