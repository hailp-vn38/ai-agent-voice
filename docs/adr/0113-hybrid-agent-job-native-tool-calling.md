# ADR 0113 — Strict Root decisions and native Child function calls

Status: Accepted for implementation, 2026-10-14.

For new `hierarchical_v2` Agent Jobs, Root Orchestrator uses server-owned strict JSON Schema (`delegate|finish`), while each Sub-Agent uses provider-native strict Function Calling for frozen, permitted safe-read Plugin Operations plus server-owned `submit_result`. Rust alone validates, persists Steps, executes plugins, joins Children and finalizes the Job. This is deliberately different from a generic vendor Agent Framework: it preserves immutable provider/plugin pins, Voice capacity, SQLite Job ledger, bounded repair and non-replayable `unknown_outcome`.

Previously the Child generated ad-hoc JSON `call_plugin|finish`, leading to arguments-format errors. Existing Voice adapters already had `ToolDefinition` and `ToolCall`, but Background collectors rejected function calls. The design adds only a Background one-shot turn interface with Chat/Responses codecs; no new execution bus, MCP bridge or DB tables. The small tool projection helper exposes a strict-compatible superset of a plugin's JSON Schema and uses the original frozen source schema for Rust-side validation. Each accepted Child LLM Turn carries exactly one function call. The function `submit_result` completes a Child Run, not an entire Job.

Provider declares `supports_structured_outputs` and `supports_function_calling` separately from existing `supports_responses`. They are opt-in assertions for the pinned model/transport and do not imply qualification. Requests fail closed if unsupported; never silently switch endpoints or drop strict validation. Legacy `dag_v1` and Voice streaming behavior remain unchanged.

Alternatives rejected: JSON actions for both Root and Child (fragile dynamic plugin arguments), tool calling for Root (unnecessary dispatch semantics), and vendor-side tool execution (bypasses Rust-owned authority). See [implementation guide](../agent-job-hybrid-implementation.md) and [operational flow](../flows/08-agent-job-hybrid.md). ADR 0099's original Background tool-free rule still applies to **legacy** completions; this decision governs hierarchical native turns. ADR 0103's hierarchical model remains authoritative.
