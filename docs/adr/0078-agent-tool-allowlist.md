# ADR 0078 — Agent tool allowlist independent of speaker identity

## Status

Superseded, 2026-10-08 by the MCP Tool Authorization refactor. The new policy retains Agent-scoped, live-guarded approval for External MCP in every Speaker Policy, but removes Device tool approval/recovery entirely.

Agent Tool Allowlist do server/admin quản lý là giới hạn thao tác của Agent độc lập với Speaker Match. Entry thuộc Agent, định danh công khai bằng `device_id` / Protocol Device Identity + tên tool gốc, hoặc External MCP `server_key` + tên tool gốc; DB dùng FK tới resource nội bộ. Không thêm Device key riêng, không dùng tên hiển thị/Client ID hoặc wildcard Device; Device mới hoặc resource delete/recreate không kế thừa quyền cũ. Chỉ tool đã được admin đánh giá và cho phép mới được quảng bá cho LLM. Kiểm lại quyền trước dispatch cho cả hai nguồn, kể cả tên tool được gọi trực tiếp. Tool chưa được đánh giá/cho phép mặc định bị từ chối; tool nhạy cảm bị chặn khi chưa có Independent Confirmation. Không suy độ an toàn từ prompt, tên hoặc nhãn read-only, vì đọc dữ liệu riêng cũng nhạy cảm.

Chọn allowlist để giới hạn rõ capability được Agent sử dụng; các bộ lọc hiện có vẫn áp dụng. Allowlist không thay thế denylist hiện có hoặc cho phép tool vốn bị cấm. Observe giữ diagnostic giọng và không cấp quyền theo giọng, nhưng vẫn chịu allowlist. Allowlist lưu trong DB, mutation có revision và conditional update. Thêm quyền áp dụng ở WS mới; giảm quyền chặn dispatch mới và đóng WS bị ảnh hưởng, không sửa nóng Session Tool Catalog. Đây là giới hạn có chủ đích với immutable-session contract: session snapshot không giữ được quyền đã bị thu hồi. Operation đã dispatch trước thu hồi không thể hoàn tác.

Mỗi entry pin fingerprint của Reviewed Tool Contract: Device resource identity + tên gốc + input schema; External MCP resource/server identity + tên tool + input schema + endpoint/transport/auth scope/reference liên quan. Description ảnh hưởng cách sử dụng thuộc nội dung review. Không đưa secret value vào fingerprint, DB hoặc report. Fingerprint dùng contract nguồn, không chỉ LLM-visible alias.

Khi server quan sát contract đổi qua configuration mutation hoặc discovery, allowlist entry mất hiệu lực; chặn dispatch mới và đóng WS bị ảnh hưởng. Admin review lại contract hiện tại bằng conditional update. Không hứa phát hiện firmware/backend đổi hành vi nhưng giữ nguyên contract hoặc phát hiện remote change trước discovery tiếp theo. Lưu observed contract metadata bounded trong SQLite từ discovery hoàn tất của WS đã admit, qua validation/bounds hiện có; không coi schema Admin nhập là bằng chứng. Admin inspect thời điểm quan sát rồi approve đúng Device incarnation + observed revision + fingerprint. Transaction kiểm lại observation và allowlist revision; observation đổi giữa lúc xem/approve trả conflict. Discovery không tự cấp quyền, không trộn các discovery chưa hoàn tất. Hai observation hợp lệ mâu thuẫn thì đánh dấu conflict, chặn entry và invalidation; không chọn kết nối mới nhất. Inspection chỉ khẳng định contract đã quan sát, không chứng minh Device online hoặc implementation hiện còn giữ hành vi. Conflict được giải quyết bằng đợt discovery riêng gắn đúng Device incarnation, có identity, deadline và trạng thái rõ ràng. Chỉ observation hoàn tất trong đợt được xét; kết quả muộn từ đợt cũ bị loại. Các discovery nhất quán tạo contract reviewable; còn mâu thuẫn, timeout hoặc chưa hoàn tất thì tiếp tục blocked, không loại kết quả lỗi để tuyên bố nhất quán. Observation cũ superseded với retention bounded. Admin vẫn conditional approve revision/fingerprint mới; không tự phục hồi allowlist. Tái dùng MCP discovery hiện có; không thêm một protocol discovery riêng.
