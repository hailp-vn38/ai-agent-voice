# 08: Session-local Template switching

**What to build:** A Voice Session can explicitly switch among its admission-validated Template candidates only at a next-turn boundary, without querying live DB state or hot-loading a Provider.

**Blocked by:** 07: Provider Load Plan và Effective Session Profile.

**Status:** ready-for-human

- [x] Admission constructs immutable Template Switch Catalog from enabled, valid, loaded non-default candidates; no-assignment Server Default Profile has empty catalog and does not advertise switch capability. The internal tool is represented as a session-local built-in/action, so Ticket 10 can preserve it while replacing the shared round executor.
- [x] Switch validates catalog membership and applies only after the current normal turn boundary; it never changes an in-flight turn or resolves Provider desired config from DB.
- [x] Successful switch atomically updates active profile snapshot and Session Profile Revision; failed switch leaves profile/revision unchanged with coarse safe error.
- [x] Admin mutation after admission cannot add/remove/alter switch candidates for that session; reconnect sees new desired/runtime availability only under established restart semantics.
- [x] WebSocket tests prove advertised/non-advertised behavior, current-turn stability, next-turn application, no SQLite query during switch, revision increments and invalid candidate exclusion.

## Comments

- `ResolvedTemplateProfile` now carries the `ResolvedAgentRuntimes` admission already resolved, so a switch installs handles that provably already exist in the Loaded Runtime catalog instead of constructing anything. `EffectiveSessionProfile::into_active_profile` splits the resolved value into the `ActiveTemplateProfile` a session runs with and the immutable `TemplateSwitchCatalog` it may switch among; `ActiveTemplateProfile::switched_to` is the single transition and advances the Session Profile Revision.
- The switch is the session-local builtin `server.switch_template` (`tools::builtin`), advertised only when the admission catalog is non-empty and only with the candidate keys this session admitted. The dotted name namespaces it as a server action and is structurally collision-free, because a Device MCP tool name is sanitized to alphanumerics, `_` and `-` before it can reach the model.
- `PendingSessionAction` became `PendingSessionActions`: an exit and a switch armed in the same turn no longer overwrite each other, and both are dropped when the turn is interrupted before its boundary. Abort semantics are unchanged — the previous code also cleared the armed action on `WriterTurnOutcome::Aborted`.
- **Runtime install is lease-safe.** A worker lease belongs to the runtime that granted it, so a runtime the candidate does not change is left completely alone, and one that does change has its open VAD/ASR lease closed on the departing runtime first. `complete_recognition` re-arms Auto/Realtime capture when the cycle was rebased, instead of leaving the client without capture or sending an unknown lease to the new runtime. `SpeechOutput::release` closes a replaced output's TTS stream so a switch cannot grow the runtime's stream registry.
- **Ingress ordering fix.** `SessionActor::run` applies already-reported writer outcomes before interpreting new client intent. The writer reports a turn's terminal outcome immediately after the client sees `tts:stop`, so a client may start the next turn at once; without this the next turn overtook the previous turn's boundary, dropped its first audio frames, and let a boundary switch land after the turn it belonged to. This is adjacent to the phase-5 barge-in ordering owned elsewhere.
- Proven at the WebSocket boundary in `tests/session_profile.rs`: non-advertised for an Agent without assignments, advertised enum exactly `["primary","sales"]`, current-turn answer stays on the old prompt/runtime, next turn runs the switched prompt on the switched already-loaded runtime, a post-admission prompt/assignment/revision mutation is ignored by the switch, an excluded candidate is neither advertised nor switchable and a rejected switch changes nothing, and an interrupted turn drops the switch it armed. Revision increments and the unchanged-runtimes case are covered at the actor seam in `session/actor/tools.rs`, where two distinct LLM and VAD instances make a runtime change observable by identity.
- `cargo check -p voice-agent-server --all-targets`, `cargo clippy --workspace --all-targets` (no new warnings), `cargo fmt --check`, `git diff --check`, targeted session profile/builtin/actor tests and `cargo test --workspace` all pass.
- Review follow-up: the first pass swapped VAD/ASR runtime pointers while their leases were still open, which sent a departed lease to a runtime that never granted it and failed an Auto session closed. Both review axes found it; it is fixed and covered by `a_switch_that_rebases_the_vad_runtime_rearms_capture_instead_of_failing_closed`, which fails against the pre-fix code.
- CONTEXT.md's "Runtime Snapshot" entry still lists a catalog-aware `SessionActor` as a term to avoid, while guide §19.2 mandates exactly that runtime swap. The guide wins for now; the glossary entry is stale and should be revisited with the next database pass. That edit was left out here because `CONTEXT.md` already carries unrelated worktree changes.
