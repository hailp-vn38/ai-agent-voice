# 07: ZeroTTS worker canonical delivery

**What to build:** Sau Ticket 06, Voice Protocol Client nhận real ZeroTTS audio qua TtsWorkerRuntime và đường SpeechOutput hiện có. Ticket này thêm codec streaming, deterministic startup warmup và native worker ownership bounded; PCM float mono 48 kHz trở thành canonical 24 kHz Opus mà không đổi outbound ownership.

**Blocked by:** 04: Streaming delivery integrity; 06: ZeroTTS synthesis-core parity.

**Status:** ready-for-human

- [x] Implement the two pinned codec decode graphs with required external shared data and metadata contract. Convert TTS codes from int64 `(B, K, T)` to the codec's int32 `(B, T, K)` form, initialize codec cached positions to `-1`, preserve EOA tail, and average/normalize codec output to finite `PcmF32Mono` at exactly 48 kHz. Codec metadata/profile or shared-data mismatch fails startup rather than falling back.
- [x] ZeroTtsFactory runs one deterministic non-user `maichi` warmup after Ticket 06 core validation and before socket bind. It exercises tokenizer, latent, all three TTS graphs, both codec graphs and external data, then validates terminal non-empty finite mono 48 kHz PCM. Mutable warmup state is closed/reset and never becomes a user lease; failure prevents bind.
- [x] TtsWorkerRuntime runs each mutable operation outside Tokio with exactly the prevalidated Ticket 06 engine contract, bounded command/capacity, timeout from worker acceptance, safe-point cancellation, cleanup acknowledgement and quarantine after cleanup grace. The native thread publishes terminal acknowledgement to a runtime-owned event boundary; only TtsWorkerRuntime/supervisor observes that acknowledgement, transitions the lease and releases or quarantines its slot before routing the terminal result to SpeechOutput. A worker must never erase its own slot, and SpeechOutput/SessionActor never owns worker-capacity release. It does not add a second admission semaphore or run ONNX on the Tokio executor.
- [ ] Run the required installed-pack/ORT real-model checks: no stale output after cancellation, no reuse before cleanup acknowledgement, and controlled overload. The real codec PCM -> canonical Opus decode now passes; the three worker lifecycle cases remain required before closing the ticket.
- [x] Application tests verify `limits.tts_concurrency` equals native worker capacity and admission leases a real worker without a second mismatched limiter. Tests cover failure before Started (no controls) and failure after Started (generation invalidated, exactly one stop, no later audio).
- [x] Add deterministic regression seams for the terminal-ack lifecycle: a controllable native-worker harness proves a slot remains occupied until runtime consumption and is then released or quarantined exactly once; the actor-level backpressure scenario uses an explicit Started/worker barrier before producing overflow, rather than scheduler timing or `yield_now`. It proves the Started path returns to Ready with one stop and no Delivered Assistant Response, while the pre-Started path returns to Ready with no playback controls.

The current experimental worker removes its own slot immediately after terminal send while SpeechOutput separately calls `finish`; this splits one lease transition between two owners. The acceptance criterion now makes the runtime-owned acknowledgement boundary explicit. The repair and a deterministic regression test are inside Ticket 07 scope; no new architecture approval is needed.
- Audit follow-up 2026-09-22: the same regression passed and failed on consecutive invocations; a 20-run loop failed immediately on the assertion that `tts:start` occurred. `BackpressuredLlm` races a freshly spawned TTS thread, so its current timing does not guarantee whether overflow happens before or after Started. This is a second test-design defect, separate from the worker ownership defect, and is now an explicit Ticket 07 acceptance requirement.
